# 智能体数据迁移到其他盘（子项目 D）

日期：2026-09-18
状态：设计已确认，待实现

## 背景

维护者机器 C 盘剩余 30.9 GB，`~/.codex` 约 13 GB、`~/.claude` 约 0.8 GB，D/E/F 盘各有 100–200 GB 空闲。两个目录都是普通目录，`CODEX_HOME` / `CLAUDE_CONFIG_DIR` 均未设置。

用户选择：

- 迁移方式：目录联接（原位置留一个指向新位置的联接），所有客户端无感，不依赖环境变量，不需要管理员权限。
- 范围：只迁数据目录 `~/.codex`、`~/.claude`，可分别迁移。桌面端程序目录（`%LOCALAPPDATA%\OpenAI\Codex`、Claude MSIX 数据）不动。
- 交接包不在本次范围内（C3 的项目交接资料已覆盖换账号继续工作）。

## 1. 入口

「会话数据 → 占用」标签，每个智能体标题旁显示数据位置与大小；按钮：

- 普通目录：「迁移到其他盘…」
- 已是 Stacker 创建的联接：「迁回原位置」；备份仍在时另有「删除 C 盘上的备份（X GB）」
- 由环境变量指向其他位置、或是其他来源的链接：只显示位置，不提供迁移

## 2. 迁移前检查

全部通过才能开始，失败项逐条显示原因：

| 检查 | 错误码 |
| --- | --- |
| 智能体已退出：Codex（任何 `codex*.exe`、Codex 桌面端）；Claude（`claude.exe`、Claude 桌面端 `Claude.exe`）。Stacker 不关闭任何程序 | `E_APP_RUNNING` |
| 原位置是普通目录（不是链接或联接）；对应环境变量未设置 | `E_NOT_MOVABLE` |
| 原目录内部的符号链接（非目录联接）无法重建时 | `E_LINK_INSIDE` |
| 目标为绝对路径，所在分区为本机 NTFS | `E_TARGET_FS` |
| 目标不存在或为空目录；不在原目录内部；原目录也不在目标内部 | `E_TARGET` |
| 目标分区剩余空间 ≥ 数据大小 × 1.1 | `E_SPACE` |

默认目标：剩余空间最多的非系统分区下 `AgentData\codex` 或 `AgentData\claude`，用户可修改。

## 3. 迁移步骤

后台任务，显示已复制字节 / 总字节。每一步完成后把状态写入 `sessions.sqlite3` 的 `settings`（键 `migration:<agent>`）：

```json
{ "agent": "codex", "source": "C:\\Users\\u\\.codex", "target": "D:\\AgentData\\codex",
  "backup": "C:\\Users\\u\\.codex.stacker-backup", "step": "copying|copied|renamed|linked|done|cleaned",
  "bytes": 0, "files": 0, "startedAt": 0 }
```

1. `copying`：递归复制到目标，保留文件修改时间。目录内部的目录联接不进入复制，而是在目标中重建：指向原目录内部的，改为指向目标中对应路径；指向外部的，保持原目标。维护者机器的 `~/.codex\plugins\cache\openai-bundled\chrome\latest` 就是指向同级版本目录的联接。其他类型的链接（符号链接）报告 `E_LINK_INSIDE` 并中止。
2. `copied`：核对目标的文件数、总字节与重建的联接数与源一致（联接内容不重复计数）。
3. `renamed`：把源目录改名为 `<源>.stacker-backup`。改名失败（文件被占用）→ 删除目标副本，状态清除，报告 `E_IN_USE`。
4. `linked`：在源路径创建目录联接指向目标；通过联接读取目标中一个文件确认可用。
5. `done`：迁移完成，备份仍在。界面提示先打开智能体确认正常，再删除备份。
6. `cleaned`：用户点击后删除备份目录。

## 4. 失败、恢复与迁回

- 任一步失败按已记录的步骤撤销：删除联接 → 备份改回原名 → 删除目标副本 → 清除状态。
- Stacker 启动后进入「占用」标签时，如发现状态停在 `copying`–`linked`，提示「上次迁移未完成」，提供「恢复原状」（同上撤销）。
- 迁回原位置：
  - 备份仍在（`done`）：删除联接，备份改回原名，目标副本保留并提示可手动删除或一键删除。
  - 备份已删（`cleaned`）：复制目标 → `<源>.stacker-restore`，核对，删除联接，改名为源，清除状态；目标副本保留并提示。
- 删除联接只删除联接本身（`RemoveDirectory`），从不递归进入目标。

## 5. 兼容性

- C1 会话列表、C2 占用统计、C3 摘要都经原路径访问，联接透明。
- C1/C2 删除的「路径必须位于根目录内」检查基于 `canonicalize`，根目录与文件都解析到新位置，检查仍成立；增加测试覆盖。
- C2 统计中该智能体的根目录显示为原路径，并标注实际位置。

## 6. 不在范围内

- 环境变量方式、桌面端程序目录迁移、交接包。

## 测试

在临时目录中：复制与核对（含子目录、修改时间）；源内联接按内部 / 外部两种情况重建；改名失败时回滚；中途状态恢复；迁回（备份在 / 已删）；删除联接不影响目标内容；联接下 C1 删除与 C2 清理的越界检查。

手动验收：迁移 `~/.claude` 与 `~/.codex` 到 D 盘，打开两个智能体的 CLI 与桌面端确认会话与登录正常，删除备份后 C 盘剩余空间增加；再迁回一次确认可逆。
