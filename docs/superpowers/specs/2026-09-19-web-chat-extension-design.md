# 子项目 G：网页对话浏览器插件 设计

日期：2026-09-19
状态：G1–G4 已实现（Grok、DeepSeek 未实测，暂不支持删除）

## 1. 目标

用一个浏览器插件管理 ChatGPT、Claude、Gemini、Grok、DeepSeek 网页版上的对话：清理、找回、整理、留存，并从长对话中提炼可复用的经验、领域要求、提示词与 skill 草稿。

**核心原则：插件与 Stacker 都能独立运行，互不依赖；两者连接后能力增强。**

- 插件单独使用：清理、搜索、整理、导出、摘录全部可用，数据存在浏览器本地。提炼不可用。
- Stacker 单独使用：与现在完全一致。
- 两者连接：网页对话进入 Stacker 统一搜索、摘要与交接；由本机智能体提炼；导出直接存盘；插件整理数据在 Stacker 备份，可恢复。

不做：导入官方数据导出包；把文件夹、标签写回网站；一键安装 skill；Firefox；商店上架（第一版）。

## 2. 已定决策

| 项 | 决定 |
|---|---|
| 功能 | 清理、找回、整理、留存、与本机会话统一管理、提炼（全部要） |
| 站点（第一版） | ChatGPT、Claude、Gemini、Grok、DeepSeek |
| 浏览器 | Chromium 内核（Chrome、Edge 等），Manifest V3 |
| 界面 | 独立管理页 + 可调大小的独立弹出窗口；网页上仅一个「选中文字存为摘录」按钮 |
| 正文读取 | 按需：打开、导出、提炼、删除前导出或用户点「读取正文」时才读；读过的缓存 |
| 删除 | 与本机会话删除一致：精简导出后删除（默认）/ 完整备份后删除 / 直接删除（二次确认） |
| 多账号 | 支持，数据按「站点 + 账号」隔离；只操作当前浏览器已登录的账号 |
| 提炼 | 只在连接 Stacker 时可用，由本机智能体执行；单独使用时只能手动摘录 |
| skill | 只生成草稿文件夹保存到本机，不安装，由用户导入智能体完善后自行决定 |
| 安装 | 随 Stacker 附带，开发者模式加载；也提供独立 zip；代码按商店规范编写 |
| 通信 | Chrome 本地消息（Native Messaging），由 Stacker 主程序的桥接模式处理 |

## 3. 结构

### 3.1 浏览器插件（仓库 `extension/`）

TypeScript + React，与 Stacker 前端同一技术栈与视觉风格，Vite 构建。

- **后台脚本（service worker）**：任务调度、限速、同步队列、连接桥接程序（连不上即视为单独使用）。
- **站点适配器**：每站一个，统一接口：
  - `account()`：当前登录账号的内部编号（不取邮箱）；
  - `list(cursor)`：对话标题、创建与更新时间、是否归档；
  - `read(id)`：正文，归一为消息列表；
  - `remove(id)`；
  - `archive(id)`（站点支持时）。

  适配器在站点页面上下文中运行，借用当前登录状态调用站点自身的网页接口；插件不保存任何凭证。每次调用校验返回结构。
- **管理页**：独立标签页，负责清理、搜索、整理、导出、查看提炼结果、同步状态。
- **弹出窗口**：`chrome.windows` 弹出式窗口，可调大小、可拖到副屏。针对当前对话打标签、写备注、摘录、发起提炼。
- **摘录按钮**：内容脚本在站点页面选中文字时显示，是插件对网页的唯一改动。
- **本地数据库**：IndexedDB。

### 3.2 桥接（Stacker 主程序的桥接模式）

- 不另做二进制：浏览器以 `stacker.exe chrome-extension://<插件 ID>/` 启动时，Stacker 进入桥接模式，只通过标准输入输出（4 字节小端长度 + JSON，单条 ≤ 1 MB）与插件通信，不启动界面、不打开窗口。
- 本地消息主机名 `com.stacker.webchat`；登记清单放在 Stacker 数据目录，`allowed_origins` 只含固定插件 ID；清单的 `path` 是当前的 `stacker.exe`。
- 直接读写 Stacker 数据（`webchat.sqlite3`，WAL 模式，与主程序并发安全）。

### 3.3 Stacker 应用

- 「会话数据」新增数据来源「网页对话」，与 Codex / Claude 本机会话统一搜索、查看、摘要、交接。
- 新增「提炼」结果库。
- 新增「连接浏览器插件」：显示插件文件夹与安装步骤、打开文件夹；分别为 Chrome、Edge 写入或删除当前用户注册表登记（写前征得同意）；显示连接状态与最近同步时间。

注册表位置：
- `HKCU\Software\Google\Chrome\NativeMessagingHosts\<host>`
- `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\<host>`

## 4. 数据

### 4.1 插件本地（IndexedDB）

- **账号**：站点、账号内部编号、用户起的备注名。
- **对话**：站点、账号、对话 ID、标题、创建时间、更新时间、是否归档；文件夹、标签、收藏、备注；正文读取时间及当时的更新时间（用于判断正文是否过期）；删除标记。
- **正文**：仅已读取的对话。消息列表（角色、文字、时间、附件名）。ChatGPT 分支对话只取当前显示分支。
- **摘录**：来源对话、文字、备注、时间。
- **文件夹、标签**：仅存在插件与 Stacker，不写回网站。
- **同步队列**：待交给 Stacker 的变更。

### 4.2 Stacker

- 数据库新表：网页账号、网页对话索引与整理字段、摘录、提炼结果。不改现有会话表。网页对话单独存放在 webchat.sqlite3。
- 正文：按 `站点/账号/对话` 存为压缩文件，位于 Stacker 数据目录，可随数据目录迁移。
- skill 草稿：数据目录下 `distill/skills/<名称>/`，含 `SKILL.md` 与 `excerpts.md`（依据原文摘录）。只写文件，不安装到任何智能体。
- 提炼结果：与网页对话同库（`webchat.sqlite3` 的 `distill_results`、`distill_sources`），本机会话与网页对话共用一个结果库。

### 4.3 同步

- 插件 → Stacker：对话索引、已读正文、整理数据、摘录、删除记录（网站上删除后 Stacker 标为已删除，保留当初导出的副本）。
- Stacker → 插件：提炼结果；整理数据恢复（重装浏览器后一键找回）。
- 合并：站点字段（标题、时间、归档、删除）以较新的列表刷新为准；整理字段（文件夹、标签、收藏、备注、备注名）按记录比较修改时间，较新者生效。
- 时机：连接时补交队列；平时有改动即小批量推送；失败留在队列重试；管理页显示「待同步 N 项」。

## 5. 流程

### 5.1 清理

1. 按站点、账号、时间、文件夹、标签筛选并勾选，支持「选中全部结果」。
2. 选择删除模式。
3. 确认框列出条数、涉及站点和账号；需要导出但未读正文的对话先读取正文；直接删除需再次确认。
4. 限速逐条执行（约 1–2 秒一条），遇限流自动退避；显示逐条结果，可随时中止。
5. 导出位置：单独使用时为浏览器下载目录下 `Stacker 网页对话/`；连接时为 Stacker 导出目录。
6. 只能删除当前浏览器已登录账号的对话；选中其他账号的对话时提示先切换。

### 5.2 搜索

- 标题：全部站点、全部账号。
- 正文：仅已读正文的对话，结果标注；未读的可一键补读。
- 筛选：站点、账号、文件夹、标签、时间、是否已读正文、收藏。
- 连接后，在 Stacker「会话数据」与本机会话统一搜索。

### 5.3 导出

单条或批量导出 Markdown（精简 / 完整），文件头含站点、账号备注名、原对话链接与时间。

### 5.4 提炼（需连接 Stacker）

1. 选择一条或多条对话，或若干摘录；选择产出类型（可多选）：经验问答、领域要求、提示词、skill 草稿。
2. 选择本机智能体、模型与推理强度：有默认值，可临时覆盖（沿用摘要设置的方式）。
3. 长对话分段提炼，再合并去重；合并只指出重复条目，不重写正文，每条结果保留全部来源。
4. 每条结果注明来源对话与原文链接。
5. 结果进入「提炼」库，默认为草稿，可编辑、删除、标为已采用。
6. skill 草稿保存为文件夹，不安装。
7. 插件在对话详情里只读地列出该对话的提炼结果（桥接请求 `distillResults`）。

## 6. 出错处理

- **适配失效**：返回结构校验不通过时，该站点标为「适配失效」，停止该站点所有读写，管理页提示等待更新；绝不在结构不明时删除。
- **限流**：自动退避；连续失败暂停任务并保留进度，可继续。
- **账号不一致**：当前登录账号与任务账号不符时立即停止并提示。
- **同步失败**：留在队列，不丢数据。

## 7. 安全与隐私

- 插件只申请这 5 个站点的主机权限，不申请全部网站。
- 不读取、不导出任何凭证，只借用页面登录状态；不存账号邮箱。
- 无统计上报；数据只在浏览器本地与 Stacker 本地之间流动。
- 桥接程序只接受固定插件 ID；注册表只写当前用户区，「断开」时删除。
- 提炼沿用执行器约束：临时空目录、无工具、不留会话。

## 8. 测试

- 适配器契约测试：脱敏的真实返回作为样本，覆盖列出、读取、删除的解析，以及结构异常时判定为适配失效。
- 桥接协议、同步合并、提炼分段与合并：Rust 与 TypeScript 单元测试。
- 实机验证：先只读；删除类只针对用户专门创建的测试对话，并事先征得同意。

## 9. 分期

每期都可独立使用，各自走「计划 → 实现 → 验收」。

| 期 | 内容 |
|---|---|
| G1 | 插件本体 + ChatGPT、Claude 适配器：标题索引、按需读正文、搜索、文件夹与标签、导出、三种删除模式、弹出窗口、摘录按钮 |
| G2 | Gemini、Grok、DeepSeek 适配器 |
| G3 | 桥接程序 + Stacker 同步：「网页对话」数据来源、统一搜索、整理数据备份与恢复、「连接浏览器插件」页面 |
| G4 | 提炼：经验问答、领域要求、提示词、skill 草稿；「提炼」结果库 |

各站点的具体网页接口在对应分期的实现计划中调研确认，不写入本设计。

## 10. 风险

- 站点网页接口非公开，改版即可能失效，需要持续维护；由适配失效检测兜底，避免误操作。
- 批量操作可能触发站点风控；以限速、退避和可中止降低风险。
- 开发者模式加载的插件不会自动更新，Chrome 可能提示停用开发者模式扩展。
