# 密钥保管（子项目 H）

日期：2026-10-01
状态：待审阅（修订 1）

## 目标

在 Stacker 里提供一个本机加密保管库，集中记录各平台的 API Key、令牌、Token 计划密钥、AK/SK 与 SSH 密钥，解决“官方只显示一次、忘了就得重新生成”。

定位是**加密记事本**：只记、不用。保管库不写入凭据管理器、不改环境变量、不改 `~/.ssh`、不调用任何平台 API；Git 页的令牌（Git Credential Manager）与它互不读写。

不在范围内：自动填充、TOTP、浏览器扩展、命令行注入密钥、共享与团队、云同步、泄露库比对、ssh-agent 与 ssh config 编辑、生成 SSH 密钥。

## 1. 入口与页面

- 侧栏底部新增「密钥保管」（页面 id `vault`，图标 `ti-shield-lock`，英文 `Key Vault`），排在「配置备份」「偏好设置」之上。
- 页面内容与边缘保持 15px。
- 页面有三种状态：未创建、已锁定、已解锁。已解锁时有两个标签：「条目」「发现」。
- 所有文案提供中英文两套；本文只列中文，英文在实现时按同样的语气写。

## 2. 密码体系

### 密钥结构

- 主密码：至少 12 个字符，带强度提示。
- 恢复密钥：160 位随机数，用 Crockford Base32 书写（不含易混的 I、L、O、U），8 组每组 4 个字符。输入时忽略大小写、空格和连字符。
- 数据密钥 DEK：256 位随机数，加密全部条目。
- 主密码与恢复密钥各自经 Argon2id（64 MiB、3 次迭代、1 线程，参数写入文件头）派生出包裹密钥，分别包裹同一个 DEK，所以二者任选其一即可解锁。
- 加密算法 XChaCha20-Poly1305，每次加密使用新随机 nonce；文件头作为附加认证数据，被篡改则解密失败。

### 文件

- 位置固定为 `%APPDATA%\stacker\vault.skv`，不提供自选位置。卸载程序的“删除应用数据”只清理 `%APPDATA%\com.stacker.app`，不影响此文件。
- 结构：魔数与格式版本、文件头（KDF 参数、两份包裹后的 DEK）、条目密文。条目只有几十到几百条，整体读写，不用数据库。
- 格式版本高于当前程序支持的文件拒绝打开，提示“此保管库由更新版本的 Stacker 创建，请先升级。”；不做降级写入。
- 写入先写临时文件并刷盘，再改名；每次保存前把上一份可用版本留为 `vault.skv.bak`。
- 保存前检查文件自上次读取后未被外部改动（比较大小、修改时间与哈希）；被改动则拒绝保存，提示“保管库文件已在外部被修改，请重新解锁后再试。”
- 非敏感设置（自动锁定时长、「发现」中添加的文件夹）存放在 `settings.json`，不进入保管库文件。

### 内存与解锁

- 解锁后的 DEK 与明文只在后端内存中，锁定时尽力清零（解析过程中产生的临时字符串无法保证全部覆盖）。
- 前端只拿到元信息；保密字段仅在“显示”或“复制”时由后端单次返回，复制由后端直接写剪贴板，前端不经手。恢复密钥的“复制”同样由后端写剪贴板。
- Tauri 命令一律在后台线程执行（Argon2id 一次约数百毫秒，不能阻塞界面线程）。
- 连续输错 5 次后等待 30 秒（仅内存计数，重启清零；真正的暴力破解成本由 Argon2id 承担）。

### 凭据生命周期

| 操作 | 需要验证 | 结果 | DEK |
| --- | --- | --- | --- |
| 解锁 | 主密码，或恢复密钥 | 进入保管库 | 不变 |
| 用恢复密钥解锁 | 恢复密钥 | 必须设置新主密码，并签发新恢复密钥，旧的作废 | 更换 |
| 修改主密码 | 当前主密码 | 恢复密钥保持有效 | 不变，只重新包裹 |
| 重置恢复密钥 | 主密码 | 签发新恢复密钥，旧的立即失效 | 更换 |
| 导出备份 | 主密码 | 备份仍由该主密码与恢复密钥保护 | 不变 |
| 导入备份 | 备份文件自己的主密码或恢复密钥 | 合并到当前保管库，不删除条目 | 不变 |

- 修改主密码时手里没有恢复密钥，无法用它包裹新的 DEK，所以只重新包裹、不更换 DEK。
- 两份包裹都会重做时（重置恢复密钥、用恢复密钥解锁）才更换 DEK 并重写整个文件，使旧恢复密钥对新文件彻底失效。此前导出的旧备份仍能被其当时的凭据打开，这一点无法避免。
- 凡是签发新恢复密钥的流程，顺序都是：生成 → 显示 → 用户输入最后一组确认 → 才写入文件。中途关闭程序时文件不变，旧凭据继续有效，不会出现“新恢复密钥还没保存就已生效”。
- 用恢复密钥解锁后，先完成“设置新主密码 → 保存新恢复密钥”，才进入保管库、显示条目；中途取消则保管库保持锁定，旧凭据继续有效。
- 主密码强度提示按长度与字符类别估算，不引入额外的强度库。

### 两样都忘了

解锁页提供「无法解锁？」→「重置保管库」：再次确认后，把现有文件改名为 `vault-YYYYMMDD-HHmmss.skv.old`（不删除，想起来以后还能导入），然后进入创建流程。

## 3. 首次创建与解锁

三步：设置主密码 → 保存恢复密钥 → 完成。保管库文件在第 ② 步确认后才写入。

次要入口「从备份文件恢复」：仅在本机还没有保管库时出现，把备份文件复制为保管库文件，沿用其主密码与恢复密钥，然后进入解锁。

| 界面 | 文案 |
| --- | --- |
| 设置主密码 | 标题“设置主密码”；说明“主密码用于加密保管库，不会保存在任何位置，请牢记。”；输入框“主密码（至少 12 个字符）”“确认主密码”；按钮“下一步” |
| 保存恢复密钥 | 标题“保存恢复密钥”；说明“忘记主密码时，可使用恢复密钥解锁保管库。恢复密钥仅显示一次；主密码与恢复密钥均丢失时，数据无法恢复。”；建议“保存至微信收藏、手机备忘录或其他密码管理器，或打印后妥善存放。”；警示“请勿与保管库文件存放在同一位置。”；确认“请输入恢复密钥的最后一组字符，以确认已保存。”；按钮“完成” |
| 解锁 | 标题“解锁保管库”；错误“主密码不正确。”；链接“使用恢复密钥”“无法解锁？”；恢复后“解锁成功。请设置新的主密码，并保存新的恢复密钥。” |
| 重置恢复密钥 | 说明“将生成新的恢复密钥，原恢复密钥立即失效。”；需输入主密码，随后进入“保存恢复密钥”界面 |
| 重置保管库 | 说明“现有保管库将改名保留，并创建一个新的空保管库。日后想起主密码或恢复密钥，可通过导入找回旧数据。” |

## 4. 条目

字段：`id`、标题、平台、类型、字段列表（名称、值、是否保密）、到期日、标签、备注、收藏、创建与修改时间、删除时间、保密字段历史。

类型与预填字段（字段都可增删改）：

| 类型 | 预填字段 |
| --- | --- |
| API Key | Key、Base URL |
| 令牌 | Token、账号、权限范围 |
| Token 计划 | Key、Base URL、套餐、额度/周期 |
| AK/SK | Access Key ID、Secret Access Key |
| SSH 密钥 | 私钥、公钥、口令、用途/主机；指纹由私钥自动计算 |
| 其他 | 空白 |

平台带常见平台预设（火山方舟、智谱、Kimi、MiniMax、OpenAI、Anthropic、GitHub、GitLab 等），也可手填。

### 条目页功能

- **列表**：标题、平台、类型、到期、更新时间；顶部搜索与「全部 / 平台 / 即将到期」筛选；收藏的条目置顶。搜索范围是标题、平台、标签、备注和非保密字段，不搜保密字段。
- **显示**：保密字段默认 `••••`，点“显示”后 30 秒自动遮回，锁定时立即遮回。
- **复制**：复制后提示“已复制，30 秒后自动清除剪贴板。”写入时设置不进入 Win+V 历史与云剪贴板。30 秒后、锁定时、退出时，仅当剪贴板内容仍是本次复制的值才清空，不误清用户之后复制的内容。
- **历史**：保密字段被修改时保留旧值，最近 10 次，带时间，需手动显示。
- **回收站**：删除先进入回收站，保留 30 天，在解锁时清除过期项；可恢复或立即清除。确认文案“删除「标题」？可在回收站保留 30 天。”；回收站内“立即清除「标题」？此操作无法撤销。”
- **到期**：14 天内到期或已过期时，列表标记，页面顶部显示“N 项凭据将在 14 天内到期。”
- **自动锁定**：
  - Stacker 窗口内无操作达设定时长（默认 10 分钟，可选 5 / 10 / 30 / 60）。
  - Windows 锁屏或系统睡眠。
  - 手动锁定。
  - 锁定后提示“空闲 10 分钟，保管库已锁定。”

## 5. SSH 密钥

- 条目内的私钥字段支持多行粘贴（上限 16 KB），原样保存，含结尾换行。OpenSSH 格式（含带口令的）文件内自带公钥，可直接得到公钥与 SHA256 指纹；PEM 格式（PKCS#1 / PKCS#8）只能识别算法与是否加密，公钥使用旁边的 `.pub` 或手填。
- 导入走「发现」标签的 SSH 来源（见第 6 节）。
- **导出私钥**：
  - 选择路径，提示“私钥将以明文写入所选位置，请确认路径安全。”，确认后才写。
  - 写入后把文件权限收紧为仅当前用户可读写，否则 Windows 版 OpenSSH 会以权限过宽拒绝使用该私钥。
  - 不覆盖已有文件。
- **体检标记**（参考 1Password Developer Watchtower）：私钥未加密、DSA、RSA 小于 2048 位。

## 6. 发现散落密钥

「发现」标签：扫描本机以明文保存的密钥，用户勾选后加密入库。**只读，不修改、不删除、不移动任何原文件。** 需要保管库已解锁。

说明文案：“扫描本机常见位置中以明文保存的密钥，选择后加密保存到保管库。扫描只读，不会修改或删除原文件。”

### 范围（用户逐项勾选后扫描）

| 来源 | 位置 | 识别 |
| --- | --- | --- |
| SSH 密钥 | `~/.ssh`，最多 3 层 | OpenSSH、PKCS#8、PKCS#1 私钥；标记未加密、DSA、RSA 小于 2048 位 |
| 云与包管理配置 | `~/.aws/credentials`、`~/.npmrc`、`~/.git-credentials`、`~/.pypirc`、`~/.cargo/credentials.toml` | 按各文件格式取密钥、令牌、密码字段 |
| 环境变量 | 当前用户与系统环境变量 | 按下方名称与取值规则 |
| 项目 `.env` | 用户添加的文件夹（记在 `settings.json`），最多 4 层；跳过 `node_modules`、`.git`、`target`、`dist`、`build`、`.venv` | `.env`、`.env.*`，排除 `.example`、`.sample`、`.template` 结尾的文件 |

明确不扫描：智能体的登录凭据（如 `~/.codex/auth.json`、`~/.claude` 下的登录文件）。它们是登录会话，不是用户签发的密钥，复制出来没有意义，反而增加泄露面。

### 识别规则

适用于环境变量与 `.env`；配置文件按其自身格式取字段，不走这套规则。

1. **名称**：按 `_`、`-`、`.` 切分后，某一段为 `KEY`、`TOKEN`、`SECRET`、`PASSWORD`、`PASSWD`、`PWD`、`CREDENTIAL`、`AUTH`，或名称包含 `APIKEY`、`ACCESSKEY`。整段匹配，避免把 `MONKEY` 这类名称误判。
2. **取值**：长度不少于 12；不是占位符（`your_…`、`xxx…`、`changeme`、`<…>`、`${…}`、`%…%`）；不是纯路径或不含凭据的 URL；字符熵不低于每字符 3 比特。
3. **已知前缀**：如 `sk-`、`ghp_`、`github_pat_`、`glpat-`、`xox`、`AIza`、`hf_`、`npm_`。命中时即使名称不匹配也算，并据此推测平台；平台和类型可在导入前修改。`AKIA`、`AKLT`、`LTAI` 这类访问密钥 ID 本身不是密钥，不作为前缀命中；AK/SK 由配置文件来源成对识别。

扫描限制：单个文件不超过 1 MB；单次最多检查 5 万个文件，超出时提示已截断；不跟随符号链接和联接点；后台运行，可随时取消。

### 结果与导入

- 按来源分组；列：勾选、来源与位置、名称、预览、状态。
  - 预览：普通密钥显示前 4 位加 `•••`，SSH 私钥显示指纹。
  - 状态：新发现 / 已在保管库 / 已在保管库（旧值）/ 已忽略，另带风险标记。
- 与保管库现有保密字段及其历史比对（内存中比较），命中的不可选。
- 默认不勾选任何项，提供“选择全部新发现”。
- **导入所选**：
  - 按来源建立条目：SSH → SSH 密钥，AWS → AK/SK，其余 → API Key 或令牌。
  - 备注自动写入“来源：<路径>”。
  - 完成提示“已导入 N 项。原文件未做任何改动。”
- **忽略所选**：把该值的 SHA-256 指纹存入保管库加密正文，之后不再提示。
- 无结果时提示“未发现明文密钥。”
- 结果只在内存，关闭标签或锁定即清空；日志只记录数量与路径，不记录值。

## 7. 备份与导入

- **导出**：验证主密码后，把当前文件复制为 `Stacker-保管库-YYYYMMDD.skv`，仍由原主密码与恢复密钥保护。说明：“备份文件由当前主密码加密，可在其他电脑导入。”
- **导入**：需要当前保管库已解锁。
  - 步骤：选择文件 → 输入该备份的主密码或恢复密钥 → 预览“新增 n / 更新 n / 相同 n” → 合并。
  - 说明：“导入仅新增和更新条目，不会删除现有条目；同一条目保留较新的版本。”
- **合并规则**：
  - 同一 `id` 保留 `updated_at` 较新的内容。
  - 保密字段历史取并集，按时间保留最近 10 次。
  - 忽略指纹取并集。
  - 本地已有条目的删除状态不受导入影响，导入不会把本地条目移进回收站；本地没有、备份中在回收站的条目，导入后进入回收站。
- 新电脑首次打开：用「从备份文件恢复」，或先建空库再导入。

## 8. 安全约束

- 保管库内容不进入日志、请求日志、AI 来源、本机网关与提炼等任何通道；AI 相关功能不得读取保管库。
- 不进入「配置备份」，不被 Stacker 的其他备份、迁移功能处理；磁盘清理与空间分析不得把 `vault*.skv*` 列为可清理项。
- 与现有凭据存储独立：不迁移、不改动 Git 页令牌（Git Credential Manager）、AI 来源密钥与私有源密码（DPAPI）。
- 解锁状态不持久化；第一版不提供“本机免输”。

## 9. 模块划分（拟）

后端 `src-tauri/src/vault/`：

- `crypto`：Argon2id、XChaCha20-Poly1305、DEK 包裹、恢复密钥编码，不含 IO。
- `format`：文件头与版本、文件读写、原子写入、外部改动检测、备份文件。
- `model`：条目、模板、历史、回收站、合并规则。
- `ssh`：私钥解析、指纹、体检、导出与权限收紧。
- `discover`：来源枚举、识别规则、结果比对，不含 UI 逻辑。
- `clipboard`：带排除格式的写入与条件清空。
- `commands`：Tauri 命令与解锁状态、自动锁定。

前端 `src/features/vault/`：创建与解锁、条目列表与编辑、历史与回收站、发现、备份对话框；页面 `src/pages/Vault.tsx`；导航、`i18n` 中英文键。

拟新增依赖：`argon2`、`chacha20poly1305`、`zeroize`、`getrandom`、`ssh-key`，版本与特性在实施计划中确认。

## 10. 测试

- **加解密**：
  - 加解密往返；错误主密码与错误恢复密钥。
  - 文件头被篡改后解密失败；更高格式版本被拒绝。
  - 修改主密码后恢复密钥仍可解锁；重置恢复密钥与恢复解锁后，旧恢复密钥对新文件失效。
  - 签发流程中途中断时文件不变。
- **文件**：
  - 写入中途中断后仍可从 `.bak` 恢复。
  - 外部改动后拒绝保存。
  - 重置保管库保留旧文件。
- **合并**：较新者胜；不删除本地条目、不改本地删除状态；历史与忽略指纹并集；历史上限；回收站到期清除。
- **SSH**：未加密 ed25519、带口令、DSA、RSA 1024 的固定样例；导出文件权限仅当前用户；不覆盖已有文件。
- **发现**：
  - 名称整段匹配（`MONKEY` 不命中）、已知前缀命中。
  - 占位符、低熵值与示例文件被忽略。
  - 符号链接不跟随、大文件跳过、文件数上限截断。
  - 已在保管库（含旧值）不可选、忽略指纹生效。
- **日志**：日志中不出现样例密钥值。
- **前端**：未解锁时不渲染任何条目；导航位置；显示后自动遮回；复制与自动锁定；创建流程的恢复密钥确认。
- **手动**：剪贴板不进入 Win+V 历史，且不误清后续复制的内容；锁屏自动锁定；导出的私钥能被 `ssh` 直接使用；换一台电脑导入备份。
