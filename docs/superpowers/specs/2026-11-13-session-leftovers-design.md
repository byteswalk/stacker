# 会话残留清理（Claude Code / Codex）

日期：2026-11-13　状态：已与用户确认方向（截图瘦身默认关闭、不活跃 7 天、手动 + 自动）

## 背景

本机实测：项目里的编译产物与依赖 24.5 GB（Rust `target` 21 GB），Codex 会话记录 10.7 GB（单个会话最大 1.4 GB，其中 944 MB 是内嵌截图），Claude 会话记录 3.8 GB（约 1 GB 内嵌截图）。

两家客户端都不清项目里的编译产物，也不清会话里的截图；Claude 从桌面端发起或续过的会话永久保留，连带它的检查点和临时目录；Codex 的会话记录从不自动删除。Stacker 的「占用」页只管两家自己的数据目录，「磁盘清理」能按项目清产物，但都不知道是哪个会话留下的。

判断标准（用户定）：清掉以后重建要不要花 token。编译产物、依赖、临时文件重建靠编译器和包管理器，不花 token，只花时间；会话正文和检查点删了就没法续聊或回退，才是真正费 token 的，不删，只做"瘦身"。

## 范围

只看 Claude（含桌面端）与 Codex 的会话。按会话记录的工作目录归到项目，每个项目列出：

| 类别 | 内容 | 默认勾选的条件 |
|---|---|---|
| 编译产物 `build` | 复用 `project_junk` 规则：`target`、`node_modules`、`dist`/`build`/`.next` 等、Python 与工具缓存 | 项目不活跃，或这个构建目录本身 N 天没写入（`node_modules` 只在安装时写入，不按此判断） |
| Rust 旧产物 `stale` | 活跃项目的 `target` 里 N 天没写入过的整个 profile 目录（如很久没编的 `release`） | 总是 |
| 增量缓存 `incremental` | 活跃项目 `target/<profile>/incremental` | 从不（编译变慢可能让智能体超时重试） |
| 虚拟环境 `environment` | `.venv` 等 | 从不（重建要重新下载） |
| 临时目录 `temp` | Claude 会话临时目录 `%TEMP%\claude\<项目>\<会话 id>` | 会话不活跃 |
| 检查点 `checkpoints` | `~/.claude/file-history/<会话 id>` | 会话超过 30 天没动 |
| 截图瘦身 `images` | 会话记录里内嵌的 base64 图片，换成同类型 1×1 小图，文字全留 | 开启瘦身且会话超过 30 天没动 |

"不活跃"：项目所有会话最近一次更新、项目里编译产物最近一次写入，都早于 N 天（默认 7）。

## 安全规则

- 项目路径不存在、是盘符根、用户主目录本身、Windows 或 Program Files 目录时跳过整个项目。
- 嵌套项目只归给最深的那个，同一个目录不重复计算。
- 正在运行的程序位于某一项里（如 `target\debug\stacker.exe`）时，该项标为"占用中"，不能勾选。
- 删除沿用 `footprint::cleanup::delete_item`：不跟随链接与重解析点，路径必须在声明的根目录里。
- 先预览拿令牌，执行前重新扫描核对：项目仍不活跃、大小变化不超过 1%。
- 瘦身逐行改写：只替换 `data:image/<类型>;base64,` 之后、以及 Claude 图片对象 `"data"` 里的 base64；改写后每行仍须是合法 JSON、行数不变；写到同目录临时文件再原子替换，被客户端占用时跳过。

## 设置与自动清理

`%APPDATA%\stacker\leftovers.json`：不活跃天数 7、检查点天数 30、瘦身开关（关）与天数 30、自动清理开关（关）、上次自动清理时间与释放量。

自动清理：开启后每天最多一次（启动后 2 分钟检查，之后每 6 小时检查），只清默认勾选的项，结果写入设置并通知页面。

## 界面

「会话数据」页新增「残留」标签：顶部可释放总量、重新扫描、清理已选；设置一行（天数、瘦身、自动清理与上次结果）；项目列表按可释放大小排序，展开后逐项勾选，显示路径、大小、说明与跳过原因。清理前确认框说明"永久删除，编译产物需要时重新构建即可"。

## 实现分块

1. 后端 `sessions/leftovers/`：`model`、`settings`、`scan`、`slim`、`clean`（预览令牌 + 后台任务）、`auto`；命令注册。
2. `project_junk`：条目增加最近写入时间。
3. 前端 `LeftoversPanel` 与标签、API、类型、翻译。
4. 测试：瘦身替换与校验、活跃判断、嵌套去重、受保护路径、占用阻止、Rust 旧 profile、默认勾选。

## 实施记录（2026-11-13）

- 真机：43 个项目、286 GB 残留，默认勾选 14 GB；扫描从 166 秒优化到约 30 秒（目录列表自带的元数据、同项目内并行、Rust `target` 一次遍历同时拿到各 profile 与增量缓存）。
- 截图瘦身在会话副本上实测：Codex 1428 MB → 476 MB（647 张），Claude 457 MB → 281 MB（612 张），逐行校验 JSON 与行数。
- 小于 1 MB 的项不列出；`stale`、`incremental` 是 `target` 的子项，不计入总量，父项勾选时自动并入。
